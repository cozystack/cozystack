The build stays on CAPK v0.1.10, commit `6dbc11c4d0cbfbdcd618566538c10b0d4a07516b`, and preserves its runtime image and API dependencies. The patch backports [guest node lookup #374](https://github.com/kubernetes-sigs/cluster-api-provider-kubevirt/pull/374), [uncordon after restart #389](https://github.com/kubernetes-sigs/cluster-api-provider-kubevirt/pull/389), and [migration before drain/delete #392](https://github.com/kubernetes-sigs/cluster-api-provider-kubevirt/pull/392). It bounds submission waiting to ten minutes, separately from the active migration and drain fallback windows, preserves each deadline across reconciles, and omits migration priority. CAPK v0.1.10 pins `kubevirt.io/api` v1.5.0, whose `VirtualMachineInstanceMigrationSpec` carries only `vmiName`; #392 sets `priority` against v1.9.0, where the field exists. The typed migration from #392 does not compile against the pinned API, which is why the patch builds the migration as an unstructured object and leaves priority to KubeVirt.

`make image` runs the backported regression tests, builds the manager, and writes the resulting tag and digest to `images/cluster-api-provider-kubevirt.tag`. The InfrastructureProvider reads that file through `spec.deployment.containers[].imageUrl`, supported by CAPI operator v0.19.0. The compressed provider manifest contains the additional VMIM create permission. Keeping the image reference out of the gzip lets the existing image collection, promotion, and nightly mirror code see and rewrite it.

The checked-in tag still points at the original upstream image, so applying the chart directly from this source tree does not install the backport. The regular main and release builds call this package's `image` target before packaging, and the release workflow commits the resulting digest pin with its other generated artifacts. A release containing the fix must therefore come from that trusted build path. Fork CI derives its repository allowlist from the base branch, so this new image repository requires a maintainer-owned build for pre-merge E2E validation; changing a fork's allowlist does not authorize publication.
