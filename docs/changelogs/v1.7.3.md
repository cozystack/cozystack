# Cozystack v1.7.3

Cozystack v1.7.3 is a security patch release on the v1.7 line with five security fixes in the monitoring, Harbor, bucket, backups and Info packages; details will be in GitHub security advisories. Read [Migration and Upgrades](#migration-and-upgrades) before upgrading.

## Security

* **Security fix in the monitoring package**: fixes a critical security issue in the monitoring package. Details will be in a GitHub security advisory, please upgrade as soon as possible ([**@kvaps**](https://github.com/kvaps) in cozystack/cozystack@9189218).

* **Security fix in the Harbor package**: fixes a high severity security issue in the Harbor package. Details will be in a GitHub security advisory, please upgrade as soon as possible ([**@kvaps**](https://github.com/kvaps) in cozystack/cozystack@aa76e62).

* **Security fix in the bucket package**: fixes a medium severity security issue in the bucket package. Details will be in a GitHub security advisory, please upgrade as soon as possible ([**@lexfrei**](https://github.com/lexfrei) in cozystack/cozystack@50fca7e).

* **Security fix in backups**: fixes a critical security issue in the backup controller. Details will be in a GitHub security advisory, please upgrade as soon as possible ([**@IvanHunters**](https://github.com/IvanHunters) in cozystack/cozystack@4a59bae).

* **Security fix in the Info package**: fixes a high severity security issue in the Info package. Details will be in a GitHub security advisory, please upgrade as soon as possible ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in cozystack/cozystack@37ca3a9).

## Development, Testing, and CI/CD

* **fix(ci): publish the release only after the stable images and chart exist**: The release page is published last, after the stable images are retagged and the chart is pushed, and a failed retag leaves the draft for a re-run ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5169, backport #5480).

* **fix(ci): push the stable chart once, so a re-run keeps cozy-installer:X.Y.Z**: A re-run of the release finalize no longer pushes the stable `cozy-installer` chart again, so `cozy-installer:X.Y.Z` keeps the digest of its first push ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5486, backport #5487).

## Migration and Upgrades

The release adds no platform migration: `migrations.targetVersion` is 61 at both v1.7.2 and v1.7.3.

* **Monitoring web UI login**: a monitoring web UI gets login credentials of its own after the upgrade, shown to tenants as a separate Secret.
* **Sign in again**: the upgrade resets sessions of that monitoring web UI, so its users have to sign in again.
* **Rotate credentials**: rotate the Grafana admin password and the API keys of that web UI issued before the upgrade, and revoke the old keys in that web UI, the upgrade does not change or revoke them.
* **Harbor**: core, jobservice and registry roll once during the upgrade, registry storage is untouched.
* **bucket**: a bucket release whose `storagePool` does not resolve to a valid class fails on its next upgrade, fix the value before upgrading.
* **Info application**: with OIDC enabled the tenant ServiceAccount token Secret is no longer created, clients that used that token need credentials of their own.
* **First Postgres backup after an upgrade from v1.7.1 or older**: v1.7.2 gave the barman-cloud sidecar new resource limits, so on a cluster that upgrades from v1.7.1 or older the first platform backup of each Postgres application after the upgrade rolls its instances. That backup fails, the next one passes. To have the restart in a maintenance window, run a backup there and then one more. Upgrades from v1.7.2 are not affected.
* **SeaweedFS metadata database restart (upgrades from v1.7.1 or older)**: v1.7.2 restarts PostgreSQL that holds SeaweedFS metadata. If this ends in failover to an asynchronous replica that is behind, S3 writes confirmed shortly before the failover can be lost. For Postgres applications that archive WAL to this S3 the lost write can be a WAL segment, so point-in-time recovery stops before it. Take a fresh base backup of Postgres applications after the upgrade. Upgrades from v1.7.2 are not affected.
