# v1.6.6 (2026-11-27)

A patch release with five security fixes (Harbor, Alerta, Velero restore-copy, COSI bucket classes and the tenant Info ServiceAccount token), mitigations for CVE-2026-114938 (OpenSearch), CVE-2026-97629 (ingress-nginx) and CVE-2026-116331 (system PostgreSQL), and a large backport of fixes for install and upgrade retries, backups and restores, monitoring and alerting, SeaweedFS, LINSTOR, tenant quotas and the dashboard. Several changes roll running workloads or change behavior on upgrade; read [Migration and Upgrades](#migration-and-upgrades) before upgrading.

## Security

* **security(info): do not render the tenant ServiceAccount token under OIDC**: With OIDC enabled the Info application no longer renders the tenant ServiceAccount token Secret, which every `use` member of the tenant could read through `tenantsecrets`, together with the rights bound to that ServiceAccount. Tokens already read are invalidated. Without OIDC the RoleBinding now names the tenant's own ServiceAccount instead of a name another tenant could claim ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in [ffdd851](https://github.com/cozystack/cozystack/commit/ffdd851ba)).

* **fix(backups): confine Velero restore-copy to the tenant's namespace subtree**: A Velero `RestoreJob` now accepts `options.targetNamespace` only if the namespace carries the tenant subtree label of the RestoreJob's own namespace, so a tenant administrator can no longer restore a backup into another tenant's namespace or overwrite an application there. Restore-copy within the tenant's own subtree keeps working (GHSA-vq9c-8j6p-r6mp, GHSA-p7mc-34g4-53vv, GHSA-4295-xcmq-8h9h; [**@IvanHunters**](https://github.com/IvanHunters) in [37e10d8](https://github.com/cozystack/cozystack/commit/37e10d82d)).

* **fix(bucket): refuse COSI classes of another SeaweedFS instance**: The bucket chart now refuses to render when a referenced `BucketClass` or `BucketAccessClass` belongs to another SeaweedFS instance, or when `storagePool` names a class that does not exist, so a crafted `storagePool` can no longer provision a bucket in a different tenant's SeaweedFS ([**@lexfrei**](https://github.com/lexfrei) in [87d62af](https://github.com/cozystack/cozystack/commit/87d62af92)).

* **security(harbor): give the inner registry its own credential and port policy**: Harbor's inner registry no longer accepts the chart's published default credential from any pod the tenant network policies let through. Each release gets a random registry password, and a CiliumNetworkPolicy limits the registry and registryctl ports to core, jobservice and trivy of the same release ([**@kvaps**](https://github.com/kvaps) in [cd77b12](https://github.com/cozystack/cozystack/commit/cd77b124e)).

* **security(monitoring): give Alerta a real signing key and its own admin password**: Alerta now signs its session tokens with a generated `SECRET_KEY` instead of the built-in `changeme`, which allowed anyone to mint an admin token. Its admin account has a dedicated password instead of reusing Grafana's, the image is pinned by digest, credentials stay out of the container log, and tenants see Alerta's login apart from its keys ([**@kvaps**](https://github.com/kvaps) in [45f3f74](https://github.com/cozystack/cozystack/commit/45f3f7424)).

* **fix(opensearch): disable the Base64 intrinsics hit by CVE-2026-114938**: OpenSearch nodes start with `-XX:-UseBASE64Intrinsics`, which turns off the vulnerable OpenJDK Base64 decoder ([**@androndo**](https://github.com/androndo) in #5373, backport #5312).

* **fix(ingress-nginx): turn off TLS session tickets for CVE-2026-97629**: The ingress-nginx controller no longer issues TLS session tickets; session resumption keeps working through the shared session cache ([**@kvaps**](https://github.com/kvaps) in #5407, backport #5312).

* **fix(platform): bump system PostgreSQL to 17.12**: The system PostgreSQL databases (Keycloak, Harbor, Grafana, Alerta, SeaweedFS) move from 17.7 to 17.12, which fixes CVE-2026-116331 ([**@androndo**](https://github.com/androndo) in #5403, backport #5312).

## Features and Improvements

* **feat(monitoring): alert when pods of one workload share a node**: A new warning alert, `PodReplicasColocated`, fires when two or more running pods of one StatefulSet, ReplicaSet, CNPG Cluster, StrimziPodSet or etcd cluster have shared a node for an hour although a schedulable node exists for each of them ([**@yankawai**](https://github.com/yankawai) in #4993, backport #5312).

* **fix(platform): accept the container gpu-operator variant in iaas**: `bundles.iaas.gpuOperatorVariant` accepts `container`, so GPUs can be served to pods from platform values without a hand-written Package. The KubeVirt `HostDevices` feature gate and `permittedHostDevices` table are emitted for the `default` and `vgpu` variants only ([**@lexfrei**](https://github.com/lexfrei) in #4101, backport #5073).

* **fix(kubevirt): let tenant admins upload a VMDisk image with virtctl**: Tenant admins and super-admins can upload an image into a VMDisk created with `source: upload` using `virtctl image-upload`, and the vm-disk notes print the command with `--no-create` ([**@yankawai**](https://github.com/yankawai) in #5114, backport #5312).

* **fix(postgres): accept a standard five-field backup schedule**: `backup.schedule` accepts a standard five-field cron such as `0 2 * * *`; the chart prepends the seconds field CloudNativePG expects. Six-field values and descriptors render as before and any other field count fails the render ([**@yankawai**](https://github.com/yankawai) in #5119, backport #5312). See the upgrade note: existing five-field values change meaning.

* **fix(seaweedfs): remove identities left behind by deleted BucketAccesses**: Install and upgrade remove S3 identities left behind by deleted BucketAccesses. The new `cosi.orphanIdentities` value (`auto`, `report`, `delete`) controls this; `auto` only reports when `filer.grpcHost` is set ([**@lexfrei**](https://github.com/lexfrei) in #4915, backport #5312).

* **fix(vm-instance): disable helm readiness wait on the VMInstance release**: VMInstance HelmReleases no longer hang `InProgress` or roll back healthy VMs, because the release no longer waits on VirtualMachine readiness. Existing releases are brought in line automatically on upgrade ([**@IvanHunters**](https://github.com/IvanHunters) in #3735, backport #5089).

* **fix(vm-instance): keep an external PortList VM valid with no ports**: An external `PortList` VM with an empty port list deploys, keeps its external IP and blocks all inbound TCP and UDP traffic ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5270, backport #5312).

* **fix(controller): carry healthCheckExprs and waitStrategy to existing releases**: Existing HelmReleases now receive `healthCheckExprs` and `waitStrategy` from their ApplicationDefinition, so vm-disk and postgres releases created earlier stop waiting on DataVolume and KEDA ScaledObject during upgrades ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5087, backport #5312).

* **fix(dashboard): link a tenant row to its detail page**: The tenant name in the tenant list links to its detail page, where Delete lives, and top-level tenants get their Edit button back ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #4004, backport #5312).

* **fix(dashboard): re-authenticate on 401 instead of failing silently**: On an expired session the console sends the user to sign in again instead of showing a stale page ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #3115, backport #5056).

* **fix(dashboard): stop requesting offline_access so logout can revoke sessions**: The dashboard and linstor-gui auth-proxies no longer request `offline_access`, so logout revokes the session. Offline sessions already issued must be revoked in Keycloak ([**@IvanHunters**](https://github.com/IvanHunters) in #3447, backport #5057).

* **fix(dashboard): raise the console nginx header buffers for large OIDC tokens**: The console no longer answers `400 request header or cookie too large` to users whose OIDC token carries many group claims ([**@lexfrei**](https://github.com/lexfrei) in #4376, backport #5062).

* **fix(monitoring): give kube-apiserver its own scrape size limit**: kube-apiserver is scraped with its own 128MB limit (`vmagent.apiserverMaxScrapeSize`) instead of the global 32MB, so a large `/metrics` no longer fires `KubeAPIDown` on a healthy API server. A new `VMAgentScrapeSizeExceeded` alert reports targets over the limit ([**@IvanHunters**](https://github.com/IvanHunters) in #4427, backport #5312).

* **fix(monitoring): route InfoInhibitor to the blackhole receiver**: `InfoInhibitor` carries severity `none` again and is routed to the blackhole, so info-level alerts no longer raise a major `InfoInhibitor` in Alerta, Telegram and Slack ([**@yankawai**](https://github.com/yankawai) in #4948, backport #5312).

* **fix(monitoring-agents): make a silent Watchdog an alarm in Alerta**: A Watchdog that stops reaching Alerta raises a major `HeartbeatFail` after about six minutes instead of an ok alert after a day ([**@yankawai**](https://github.com/yankawai) in #5102, backport #5312).

* **fix(monitoring): select the vmalert Service the operator creates**: The vmalert `VMServiceScrape` matches the Service the operator creates, so vmalert metrics are collected again ([**@yankawai**](https://github.com/yankawai) in #5094, backport #5312).

* **fix(etcd): scope tenant alerts to their scrape job**: Tenant etcd alerts are scoped to their release, and duplicate tenant peer RTT alerts from the global rules are gone ([**@yankawai**](https://github.com/yankawai) in #5183, backport #5312).

* **fix(etcd): stop counting canceled watch streams as failed gRPC requests**: `etcdHighNumberOfFailedGRPCRequests` counts only the gRPC codes the etcd mixin counts, so a stopping Kubernetes API server no longer fires it on every member ([**@yankawai**](https://github.com/yankawai) in #4985, backport #5312).

* **fix(piraeus-operator): keep the LINSTOR error-report alerts quiet when the controller pod moves**: LINSTOR error-report alerts count reports per node and no longer fire on old reports when the controller moves, a scrape label changes or a satellite reconnects ([**@yankawai**](https://github.com/yankawai) in #4963, backport #5312).

* **fix(kubernetes, monitoring): send tenant cluster metrics to the tenant's vminsert**: The vmagent of tenant Kubernetes clusters writes to the tenant's vminsert and labels series with the owning tenant, so tenant cluster metrics reach the tenant's Monitoring ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5024, backport #5312).

* **fix(vertical-pod-autoscaler): run two admission controllers spread over nodes**: The VPA admission controller runs two replicas spread over nodes with a PodDisruptionBudget, so pods created during a drain still get recommendations ([**@yankawai**](https://github.com/yankawai) in #5098, backport #5312).

* **fix(tcp-balancer): cap HAProxy fds and threads by the pod's own limits**: HAProxy takes its fd and thread caps from the replica's own memory and CPU limits, so a small balancer is no longer OOMKilled on nodes with many CPUs ([**@yankawai**](https://github.com/yankawai) in #5005, backport #5312).

* **fix(ingress): restore visitor IPs through SSL passthrough**: Visitor IP handling for Cloudflare-proxied HTTPS through ssl-passthrough works again, and spoofed `CF-Connecting-IP` headers are rejected before IP whitelists ([**@toribru**](https://github.com/toribru) in #5443, backport #5312).

* **fix(ingress-nginx): raise client keepalive_time above the 1h default**: `keepalive_time` is 12h instead of 1h, so long-lived HTTP/2 connections such as kopia maintenance against S3 are no longer cut by a GOAWAY ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5250, backport #5312).

## Fixes

### Install and upgrade resilience

* **fix(kubernetes): retry the tenant CSI install instead of uninstalling it**: The tenant CSI HelmRelease retries a failed install instead of uninstalling between attempts, so the CSI node plugin and propagated StorageClasses survive. A failed CSI upgrade now retries every 30s instead of rolling back ([**@lexfrei**](https://github.com/lexfrei) in #3581, backport #5089).

* **fix(harbor): retry the nested system install instead of uninstalling it**: A slow first Harbor install no longer deletes the Redis volume and starts over ([**@lexfrei**](https://github.com/lexfrei) in #3621, backport #5089).

* **fix(tenant): retry failed etcd and seaweedfs installs in place**: A slow first install of a tenant's etcd or SeaweedFS no longer runs the cleanup hooks that delete the etcd data volumes, SeaweedFS volumes and the filer metadata database ([**@lexfrei**](https://github.com/lexfrei) in #3630, backport #5089).

* **fix(tenant): retry failed monitoring and gateway installs in place**: A slow first install of a tenant's monitoring or gateway no longer deletes the metrics and logs volumes or the ACME account key ([**@lexfrei**](https://github.com/lexfrei) in #3633, backport #5312).

* **fix(tenant): stop the gateway release waiting on TenantGateway listeners and certificates**: The tenant gateway release no longer times out on upgrade while listener certificates are pending; it waits only until the controller has observed the current TenantGateway spec ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5086, backport #5312).

* **fix(tenant): skip Cilium policies on isp-hosted without Cilium**: The tenant chart installs on the isp-hosted variants when the host has no Cilium; the Cilium policies are created only if the host serves the Cilium policy API, otherwise tenants get no network isolation from Cozystack ([**@lexfrei**](https://github.com/lexfrei) in #4710, backport #5080).

* **fix(platform): stop treating a failed ConfigMap read as a fresh cluster**: A transient API error while the migration Job reads the `cozystack-version` ConfigMap fails the pod so the Job retries, instead of stamping the target version and skipping pending migrations ([**@lexfrei**](https://github.com/lexfrei) in #4792, backport #5078).

* **fix(platform): do not gate cert-manager-issuers on ClusterIssuer readiness**: An unreachable ACME endpoint no longer holds other platform packages in `DependencyNotReady` ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5210, backport #5312).

* **fix(platform): remove the dead registries value and patch-containerd Secret**: Removes an unused `registries` value and the `patch-containerd` Secret from the platform chart ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5190, backport #5312).

* **fix(operator): rebuild each changed ArtifactGenerator generation once**: An ArtifactGenerator is rebuilt once after each spec change, so an upgrade no longer leaves a component on artifacts built from the previous spec ([**@lexfrei**](https://github.com/lexfrei) in #4594, backport #5076).

* **fix(cluster-api): resync capi-operator every minute**: A provider left not ready across an operator restart recovers in about two minutes instead of twenty ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #4939, backport #5081).

* **fix(capi): ship the core provider manifests the repository actually holds**: New installs get the core provider `startupProbe`; a running core provider keeps its manager without the probe until the provider's version moves ([**@themoriarti**](https://github.com/themoriarti) in #4483, backport #5063).

* **fix(cilium): pass the CiliumNode list to jq on stdin in the IPAM hook**: The IPAM migration hook no longer fails with "Argument list too long" on clusters with more than a few nodes, which blocked the Cilium upgrade ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5212, backport #5312).

* **fix(keycloak, foundationdb): apply operator CRD updates on upgrade**: keycloak-operator and foundationdb-operator replace their CRDs on upgrade; clusters upgraded from before v1.2.0 kept the old Keycloak CRDs, under which realm session settings were dropped, and clusters from before v1.6.0 kept old foundationdb-operator CRDs ([**@yankawai**](https://github.com/yankawai) in #4946, backport #5312).

* **fix(kamaji): drop kubelet config fields older tenants do not know**: Cozystack stops writing kubelet config fields such as `memoryReservationPolicy` that tenant Kubernetes versions before v1.36 do not know ([**@lexfrei**](https://github.com/lexfrei) in #4896, backport #5312).

* **fix(cozy-lib): make the cozyconfig helpers survive uninjected values**: The helpers return their empty defaults when `_cluster` or `_namespace` is not injected, so a chart can be rendered and unit-tested on its own ([**@lexfrei**](https://github.com/lexfrei) in #3647, backport #5141).

* **fix(cozy-lib): render tenant hugepages quota only as requests**: A tenant quota with `hugepages-2Mi` or `hugepages-1Gi` renders only `requests.hugepages-<size>`, so the tenant installs ([**@yankawai**](https://github.com/yankawai) in #5189, backport #5312).

* **fix(controller, platform): give unbounded pool members the root's LimitRange**: Sub-tenants without their own resourceQuotas receive the parent pool's container defaults, so pods that omit a limit, such as the postgres barman-cloud sidecar, are no longer rejected ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5265, backport #5312).

* **fix(api): read pool usage under the quota key the controller counts**: Tenant quota admission counts the parent pool's usage of extended resources and hugepages, so a child tenant can no longer get a share the parent already used ([**@lexfrei**](https://github.com/lexfrei) in #5184, backport #5312). See the upgrade note.

* **fix(api): validate workload memory before storing an application**: New workload memory values below 1Mi are rejected; updates to unrelated fields on existing applications still pass ([**@yankawai**](https://github.com/yankawai) in #5348, backport #5312).

* **fix(api): make monitor watch versions usable as delete preconditions**: A resourceVersion from a WorkloadMonitor-triggered Application watch event works as a delete precondition ([**@lexfrei**](https://github.com/lexfrei) in #5326, backport #5312).

* **fix(api): pass the stored object to UpdatedObject in tenantsecret Update**: Updating a tenant secret passes the stored object to `UpdatedObject` ([**@lexfrei**](https://github.com/lexfrei) in #4603, backport #5075).

* **fix(securitygroups): reject port ranges and malformed FQDNs on the SecurityGroup path**: A port range gets a clear error, and a malformed `toFQDNs` `matchName` or `matchPattern` is rejected on the SecurityGroup instead of failing on the CiliumNetworkPolicy ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5134, backport #5312).

* **fix(lineage, kubernetes): resolve CAPK node VMs to their cluster**: virt-launcher pods of Kubernetes worker nodes resolve to their Kubernetes application, so a SecurityGroup attached to a Kubernetes cluster also applies to its worker nodes ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5124, backport #5312).

### Tenant Kubernetes

* **fix(kubernetes): apply the worker TalosConfigTemplate server-side in the kubernetes chart**: The talos-reconcile Job applies the worker TalosConfigTemplate server-side, so it is no longer OOMKilled on management clusters with many CRDs after every upgrade ([**@yankawai**](https://github.com/yankawai) in #4961).

* **fix(kubernetes): reconcile KCCM EndpointSlices when tenant node VMIs change**: LoadBalancer EndpointSlices follow the VMIs backing tenant nodes instead of keeping stale addresses that blackhole traffic ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #3500, backport #5053).

* **fix(kubernetes): raise kubevirt-csi API client rate limits**: Higher QPS/Burst (tunable with `--kube-api-qps` and `--kube-api-burst`) stop bursts of volume attaches from timing out as `FailedAttachVolume` ([**@lexfrei**](https://github.com/lexfrei) in #3428, backport #5055).

* **fix(kubernetes): bound the remaining pre-delete hook deletions**: A stuck finalizer on a DataVolume, LoadBalancer Service or KamajiControlPlane no longer blocks the uninstall ([**@lexfrei**](https://github.com/lexfrei) in #3604, backport #5060).

* **fix(kubernetes): move the OIDC users out of the bootstrap Job's script**: The OIDC bootstrap Job starts for clusters with about 240 or more `oidc.users`, since bindings now come from a mounted ConfigMap ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5213, backport #5312).

* **fix(kubernetes): remove cilium dependency from coredns HelmRelease**: Removes a circular startup deadlock when Hubble Relay is enabled ([**@anikethinge**](https://github.com/anikethinge) in #5331, backport #5312).

* **fix(monitoring-agents): let the release uninstall when the VictoriaMetrics operator is gone first**: Disabling the Monitoring Agents addon no longer leaves the release in `UninstallFailed`; a pre-delete hook releases finalizers, and the VPA renders only when its CRD is served ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5152, backport #5312).

* **fix: typo in monitoring-agents values.yaml**: Corrects a typo in the monitoring-agents values ([**@gireassen**](https://github.com/gireassen) in #4799, backport #5089).

### Backups and restores

* **fix(backups): create no driver object for a job that already finished**: A BackupJob or RestoreJob just marked Failed no longer gets a driver object from the next reconcile, which could retry the failed step and leave an untracked Velero Backup or halt a VM ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #4673, backport #5312).

* **fix(backups): delete the Velero backup of a failed BackupJob**: A BackupJob whose Velero backup ends Failed, PartiallyFailed or FailedValidation asks Velero to delete it and its data; failures raise a `VeleroBackupDeletionFailed` event and retry with growing backoff ([**@androndo**](https://github.com/androndo) in #5364, backport #5312). See the upgrade note.

* **fix(backups): fail Velero RestoreJob rename for non-VMInstance kinds**: A RestoreJob requesting another `targetApplicationRef.name` for Postgres, MariaDB, ClickHouse, MongoDB or VMDisk fails explicitly instead of reporting Succeeded under the original name ([**@androndo**](https://github.com/androndo) in #4426, backport #5064).

* **fix(backups): hold a BackupJob while its application is being restored**: A not-yet-started BackupJob waits (`Ready=False`, `RestoreInProgress`) while a RestoreJob restores the same application ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #4544, backport #5066).

* **fix(backups): refuse a foreign -orig PVC and record the kept disk's reclaim policy**: An in-place VM restore with `keepOriginalPVC` fails before the VM is halted when the `-orig` PVC already exists and was not created by this RestoreJob; the earlier reclaim policy is recorded in `backups.cozystack.io/original-reclaim-policy` ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #4671, backport #5079).

* **fix(backups): give the barman-cloud sidecar an explicit CPU limit**: The Postgres barman-cloud sidecar has a one-core CPU limit instead of the LimitRange's 250m, so full backups and WAL archiving are faster ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5280, backport #5312). See the upgrade note.

* **fix(clickhouse): restore the archive a Backup was taken as**: A RestoreJob restores the archive its Backup recorded rather than the newest one; older Backups are restored best effort ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5208, backport #5312).

* **fix(clickhouse): assign DB_LIST so backup retention cleanup runs**: The scheduled backup cleanup now prunes old snapshots according to the configured retention ([**@scooby87**](https://github.com/scooby87) in #3760, backport #5058).

* **fix(clickhouse, workloadmonitor): add the cluster domain to keeper hosts and stop a PVC nil dereference**: Keeper hostnames include the cluster domain, and the WorkloadMonitor controller no longer panics on a PVC without a storage class ([**@lexfrei**](https://github.com/lexfrei) in #4608, backport #5065).

* **fix(mariadb): fail backup and restore jobs whose operator Job failed**: A failed operator Job ends the MariaDB BackupJob or RestoreJob as Failed, and a failed backup no longer creates a Ready Backup without an archive ([**@scooby87**](https://github.com/scooby87) in #5207, backport #5312).

* **fix(postgres): keep users.app's password across pod restarts**: A user named `app` keeps its password, because the chart hands CNPG the password stored in `<release>-credentials` ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #4984, backport #5312).

* **fix(postgres): render the declared databases in a stable order**: An upgrade that leaves databases unchanged no longer rewrites the init-script Secret ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5091, backport #5312).

### Databases and storage

* **fix(mariadb): let mariadb-operator watch the credentials Secret**: A changed user password is applied as soon as the credentials Secret changes, not up to about 11 hours later ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5341).

* **fix(mariadb): correct webhook cert-manager override key path**: cert-manager is actually used for the mariadb-operator webhook certificate ([**@chathurabuddi**](https://github.com/chathurabuddi) in #4537, backport #5312).

* **fix(mariadb-operator): derive the cluster name from the platform domain**: The operator uses `networking.clusterDomain` instead of a hard-coded `cozy.local`, so replication and User/Database/Grant reconciliation work with a non-default domain ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5123, backport #5312).

* **fix(opensearch): give the securityconfig update job its own resources**: The job is no longer OOMKilled at the tenant memory default, which left new clusters with security uninitialized ([**@IvanHunters**](https://github.com/IvanHunters) in #4228, backport #5059).

* **fix(opensearch-operator): align DNS_BASE with the platform cluster domain**: The operator's `DNS_BASE` follows `networking.clusterDomain`, so the securityconfig job and OpenSearch Dashboards work on installations that use `cozy.local` ([**@lexfrei**](https://github.com/lexfrei) in #4185, backport #5072). See the upgrade note.

* **fix(opensearch-operator): let a permanently yellow cluster restart**: A single-replica OpenSearch release is no longer stuck before rolling restarts once an index leaves it yellow ([**@lexfrei**](https://github.com/lexfrei) in #4317, backport #5074).

* **fix(qdrant): scrape TLS metrics over HTTPS**: Metrics scraping works again for TLS-enabled instances ([**@yankawai**](https://github.com/yankawai) in #5340, backport #5312).

* **fix(etcd): size the defrag job for the client it runs**: The tenant etcd defrag job requests 10m and 32Mi, so it runs in nearly exhausted tenant quotas ([**@yankawai**](https://github.com/yankawai) in #5100, backport #5312).

* **fix(seaweedfs): keep Object Lock working for COSI credentials on SeaweedFS 4.48**: Existing bucket credentials get the Object Lock actions SeaweedFS 4.48 requires, keeping their bucket restrictions ([**@lexfrei**](https://github.com/lexfrei) in #4893, backport #5312).

* **fix(seaweedfs): bump the COSI driver to v0.4.0 for the lost-grant fix**: Bucket users granted together no longer get S3 keys that fail with `403 InvalidAccessKeyId` ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5284, backport #5312).

* **fix(bucket): stop the ACME cleanup hook from talking to localhost, and gate the class**: The ACME cleanup hook reaches the apiserver instead of reporting success while doing nothing ([**@IvanHunters**](https://github.com/IvanHunters) in #4289, backport #5312).

* **fix(harbor): give the nginx proxy explicit resources so it survives the tenant LimitRange**: The nginx proxy and portal are no longer OOMKilled by the 128Mi LimitRange default ([**@IvanHunters**](https://github.com/IvanHunters) in #4095, backport #5312).

## Migration and Upgrades

This release adds no platform migrations. Upgrading rolls or changes the following on running clusters:

* **OpenSearch**: every OpenSearch cluster restarts once to apply `-XX:-UseBASE64Intrinsics` (#5373). On installations that use `cozy.local`, an existing `<release>-securityconfig-update` Job already stuck on the old hostname is not recreated by the operator: delete it once by hand (#4185).
* **System PostgreSQL**: the Keycloak, Harbor, Grafana, Alerta and SeaweedFS databases move to 17.12; replicas roll first, then the primary restarts in place, with an interruption of a few minutes per database (#5403).
* **Harbor**: the inner registry password is rotated on upgrade, so core, jobservice and registry roll together; registry storage is untouched ([**@kvaps**](https://github.com/kvaps), [cd77b12](https://github.com/cozystack/cozystack/commit/cd77b124e)).
* **Alerta**: Alerta gets a generated signing key and a dedicated admin password, kept in its Secret across upgrades; tokens signed with the old `changeme` key stop being valid ([45f3f74](https://github.com/cozystack/cozystack/commit/45f3f7424)).
* **Info application**: with OIDC, the tenant ServiceAccount token Secret is removed, which invalidates tokens already read; consumers of that token must switch to their own credentials (ffdd851).
* **bucket**: an existing bucket release that references a class of another SeaweedFS instance, or a `storagePool` whose class does not exist, fails on its next upgrade ([87d62af](https://github.com/cozystack/cozystack/commit/87d62af92)).
* **tcp-balancer**: the pods roll once; `maxconn` now follows the memory limit (about 16 connections per MiB) (#5005).
* **PostgreSQL backups**: a `backup.schedule` that already has five fields takes the standard meaning on upgrade, so `0 2 * * *` moves from hourly to daily (#5119). Each instance pod of a tenant with a CPU quota counts 750m more against `limits.cpu` because of the barman-cloud sidecar limit; check the headroom before instance pods are recreated (#5280).
* **Tenant quotas**: after upgrading, updates to existing tenants may be rejected if their quota for extended resources or hugepages exceeds the parent's remaining budget, including updates that leave the quota unchanged (#5184).
* **Velero**: Velero backups of BackupJobs that already failed are deleted after upgrading; copy one first if you want to keep it for a manual `velero restore` (#5364). Backups created by failed MariaDB runs before this release are not removed, and restoring from one can fail or select another dump (#5207). The `backupstrategy-controller` ClusterRole gains `delete` on `deletebackuprequests`.
* **Backup restores**: when a restore with `keepOriginalPVC` keeps a disk, set the PV's reclaim policy back from the `backups.cozystack.io/original-reclaim-policy` annotation before deleting the `-orig` PVC, or its volume is not reclaimed (#4671). ClickHouse Backups taken before this release are restored best effort from the newest archive stamped no later than their `takenAt` (#5208).
* **Tenant CSI**: a failed CSI upgrade in a tenant cluster now retries the new manifests every 30s instead of rolling back (#3581).
* **Tenant super-admins** can no longer create, edit or delete `kubevirt.io` VirtualMachines directly; they keep read and watch and manage VMs through VMInstance and VMDisk (#4797).
* **Dashboard sessions**: offline sessions already issued to users must be revoked manually in Keycloak (#3447).
* **Core provider**: running Cluster API core providers keep their manager without the new `startupProbe` until the provider's version moves (#4483).
* **LINSTOR**: volumes restored from a snapshot before this release may still have an empty replica marked UpToDate; see the repair steps linked in #4866.
* **SeaweedFS**: `cosi.orphanIdentities` defaults to `auto`, which removes orphaned identities unless `filer.grpcHost` is set; set `report` if the filer is reachable from other clusters some other way (#4915).
