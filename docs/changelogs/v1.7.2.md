# Cozystack v1.7.2

Cozystack v1.7.2 is a patch release on the v1.7 line. It carries the security rebuilds of ingress-nginx and OpenSearch, Talos v1.14.4 (CVE-2026-99999) and PostgreSQL 17.12 for the platform's own databases, makes worker pool rollouts bring a replacement up before draining a node, repairs ClickHouse backup retries, adds opt-in enforcement of SeaweedFS bucket lifecycle rules, and fixes a long list of tenant-facing issues in networking, monitoring, etcd, storage and the API. Tenant PostgreSQL stays on the v1.7.1 images: the move to patched trixie images was taken back out of the line before this release.

## Features and Improvements

* **Surge one worker at a time during a pool rollout**: a `KubernetesNodes` pool rollout (instance type, image or version change) now brings each replacement worker up before it drains an old one, and adds one replacement at a time whatever the pool's size, so the extra capacity a rollout uses in the tenant's namespace is bounded. A rollout needs room for one extra VM, and large pools roll out more slowly. The new `maxUnavailable` value (default 0, and 1 on a pool with `gpus`, whose replacement may need the GPU the old worker holds) trades that headroom for the old behaviour ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5153 and #5399, backport #5311).
* **SeaweedFS bucket lifecycle rules can be enforced**: Simple and MultiZone SeaweedFS instances run the SeaweedFS admin server and a lifecycle worker when the new `lifecycle.enabled` value is set, so lifecycle rules that were stored but ignored start to apply. It is off by default because the upstream daily expiry walk can delete an object that was overwritten after it listed it. The s3 gateway's internal gRPC now runs over mTLS regardless of the switch, which repairs IAM cache propagation between s3 replicas ([**@scooby87**](https://github.com/scooby87) in #5228, backport #5311).
* **Orphaned S3 identities are cleaned up**: install and upgrade remove S3 identities left behind by deleted BucketAccesses. The new `cosi.orphanIdentities` value (`auto`, `report`, `delete`) controls it; `auto` only reports on a filer published to Client-topology clusters ([**@lexfrei**](https://github.com/lexfrei) in #4915, backport #5311).
* **Alert for pods of one workload sharing a node**: the new `PodReplicasColocated` warning fires when two or more running pods of one StatefulSet, ReplicaSet, CNPG Cluster, StrimziPodSet or etcd cluster have shared a node for an hour while a schedulable node exists for each ([**@yankawai**](https://github.com/yankawai) in #4993, backport #5311).
* **Tenant etcd spreads its members over nodes by default**: members created after the upgrade use `whenUnsatisfiable: DoNotSchedule`, so two members of one etcd no longer start on the same node while another node has none. Existing members are not moved, and a member recreated on a cluster that grew after the etcd was created can stay Pending; see the upgrade notes ([**@yankawai**](https://github.com/yankawai) in #4986, backport #5311).
* **Five-field backup schedules for PostgreSQL**: `backup.schedule` accepts a standard five-field cron such as `0 2 * * *`, and the chart prepends the seconds field CloudNativePG expects. Six-field values and descriptors render as before, and any other field count fails the render ([**@yankawai**](https://github.com/yankawai) in #5119, backport #5311).
* **Velero backup of a failed BackupJob is deleted**: a BackupJob whose Velero backup ends Failed, PartiallyFailed or FailedValidation asks Velero to delete that backup and its data in the bucket instead of leaving them until the TTL expires. A completed backup is never deleted this way. When Velero cannot delete it, the BackupJob gets a `VeleroBackupDeletionFailed` Warning event and the deletion is retried at a growing interval of up to one hour ([**@androndo**](https://github.com/androndo) in #5364, backport #5311).
* **Tenant admins can upload a VMDisk image with virtctl**: the tenant admin and super-admin roles can `virtctl image-upload` into a VMDisk created with `source: upload`, and the vm-disk notes print the matching command ([**@yankawai**](https://github.com/yankawai) in #5114, backport #5311).
* **VPA admission controller runs two replicas**: the VerticalPodAutoscaler admission controller runs two replicas spread over nodes behind a PodDisruptionBudget, so pods created during a drain still get their recommendation ([**@yankawai**](https://github.com/yankawai) in #5098, backport #5311).
* **Silent Watchdog raises an alarm in Alerta**: a Watchdog that stops reaching Alerta raises a major `HeartbeatFail` about six minutes later instead of an ok alert after a day ([**@yankawai**](https://github.com/yankawai) in #5102, backport #5311).
* **Container defaults for sub-tenants without a quota**: sub-tenants without their own `resourceQuotas` receive their parent pool's LimitRange together with the allocated quota, when that quota bounds a CPU or memory limit, so pods that omit such a limit, such as the PostgreSQL barman-cloud sidecar, are no longer rejected at admission ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5265, backport #5311).

## Fixes

* **Ingress client IPs through SSL passthrough**: visitor IPs of Cloudflare-proxied HTTPS are restored when traffic goes through ssl-passthrough, and spoofed `CF-Connecting-IP` headers are rejected before IP whitelists are evaluated ([**@toribru**](https://github.com/toribru) in #5443, backport #5311).
* **cert-manager-issuers no longer gates other packages**: the release does not wait for ClusterIssuers to become Ready, so an unreachable ACME endpoint, staging included, no longer holds other platform packages in `DependencyNotReady` ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in #5210, backport #5311).
* **Tenant super-admin VirtualMachine grant is read-only**: tenant super-admins can no longer create, edit or delete `kubevirt.io` VirtualMachines directly, and keep read and watch. VMInstance and VMDisk applications manage virtual machines, and the start/stop/restart actions manage power. The install e2e fails when a super-admin gains a write verb outside a checked-in allowlist ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #4797, backport #5311).
* **Tenant LimitRange follows the compute quota**: the LimitRange defaults cpu, memory and ephemeral-storage only when `resourceQuotas` bounds that resource, so a quota without memory no longer gives containers a 128Mi default memory limit that kept VMs from starting ([**@GitNimay**](https://github.com/GitNimay) in #4954, backport #5311).
* **Harbor registry storage is metered again**: the registry BucketClaim carries the registry WorkloadMonitor's `release` and `component` labels, so its storage shows up as a Workload and is billed, and the registry monitor reports not operational while the claim is not provisioned ([**@crossRT**](https://github.com/crossRT) in #5392, backport #5311).
* **Bucket readiness in WorkloadMonitor**: a Bucket application reports `WorkloadsReady=False` with reason `BucketClaimNotReady` until its BucketClaim is provisioned ([**@yankawai**](https://github.com/yankawai) in #5096, backport #5311).
* **Workload memory is validated before storing an application**: new memory values below 1Mi are rejected at admission, while updates to unrelated fields of existing applications with such values still pass ([**@yankawai**](https://github.com/yankawai) in #5348, backport #5311).
* **Edge TenantGateway listener**: the edge listener gets its own copy of the allowed routes; the rendered Gateway configuration is unchanged ([**@7487**](https://github.com/7487) in #4167, backport #5311).
* **WorkloadMonitor watch versions as delete preconditions**: the `resourceVersion` of an Application watch event triggered by a WorkloadMonitor works as a delete precondition, and the event's spec matches its version ([**@lexfrei**](https://github.com/lexfrei) in #5326, backport #5311).
* **LINSTOR NFS server wait container**: the `linstor-wait-node-online` init container of the NFS server runs the platform-built linstor-csi image instead of the operator's default ([**@Adham-Kiwan**](https://github.com/Adham-Kiwan) in #5358, backport #5311).
* **Wildcard certificate with child tenants**: the DNS-01 wildcard Certificate no longer lists a child tenant's apex that the parent's wildcard already covers, so Let's Encrypt stops refusing the order and the parent Gateway gets its certificate again ([**@somaz94**](https://github.com/somaz94) in #5148, backport #5311).
* **cozystack-api survives an invalid ApplicationDefinition**: a definition with an unparseable `release.cozystack.io/*` annotation or an invalid `openAPISchema` is skipped and logged instead of stopping the API from starting ([**@Adham-Kiwan**](https://github.com/Adham-Kiwan) in #5357, backport #5311).
* **LINSTOR certificate rotation**: `linstor-affinity-controller` and `linstor-scheduler` restart when their LINSTOR client certificate is rotated, instead of failing every LINSTOR API call with EOF once the certificate they loaded at startup expires ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5160, backport #5311).
* **SeaweedFS Lance catalog**: the Lance catalog ingress and the worker's Lance namespace URL point at the renamed `<name>-s3` Service ([**@Adham-Kiwan**](https://github.com/Adham-Kiwan) in #5356, backport #5311).
* **PostgreSQL `app` user keeps its password**: a user named `app` no longer loses its password when the pod restarts; the chart hands CloudNativePG the password stored in `<release>-credentials` ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #4984, backport #5311).
* **SecurityGroup validation**: a port range gets a clear "port ranges are not supported" error, and a malformed `toFQDNs` `matchName` or `matchPattern` is rejected on the SecurityGroup instead of failing on the backing CiliumNetworkPolicy ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5134, backport #5311).
* **VPA admission webhook timeout**: the timeout is 5s, so pod creation does not stall cluster-wide while the admission controller is unreachable ([**@yrahman82**](https://github.com/yrahman82) in #5242, backport #5311).
* **SeaweedFS survives its memory limit**: `GOMEMLIMIT` is set on the master, volume (each pool and zone), filer, s3 and the lifecycle admin and worker, so the Go runtime collects before the container is OOM-killed ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #4234, backport #5311).
* **SeaweedFS Object Lock on 4.48**: existing bucket credentials are granted the Object Lock actions SeaweedFS 4.48 requires on install and upgrade, keeping their bucket restrictions and keys ([**@lexfrei**](https://github.com/lexfrei) in #4893, backport #5311).
* **SeaweedFS master crash**: masters no longer crash with "concurrent map read and map write" under write load, which made S3 answer 500 ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5308, backport #5311).
* **ClickHouse backup retries**: failed backup attempts are no longer uploaded to the bucket when the backup sidecar restarts, local backups no longer accumulate on the data volume, the backup strategy waits for an idle sidecar instead of failing with HTTP 423, and a retried restore or backup takes over the operation still running instead of starting it twice. ClickHouse pods with backups enabled restart once on upgrade ([**@scooby87**](https://github.com/scooby87) in #5229, backport #5311).
* **Unquoted `false` in `ingress-enabled` and `monitoring-enabled`**: an unquoted `false` in `_cluster.ingress-enabled` or `_cluster.monitoring-enabled` now turns off the tenant-root ingress key and the monitoring redirects ([**@yankawai**](https://github.com/yankawai) in #5354, backport #5311).
* **tenant-root without ingress**: a root tenant without ingress no longer leaves `seaweedfs-system` waiting for an `ingress-nginx-system` release that is never created. Set the new platform value `ingress.rootEnabled` to `false` to match `Tenant/root` `spec.ingress: false` ([**@scooby87**](https://github.com/scooby87) in #5226, backport #5311).
* **CoreDNS of tenant clusters**: the CoreDNS HelmRelease no longer depends on Cilium, which removes a circular startup deadlock when Hubble Relay is enabled ([**@anikethinge**](https://github.com/anikethinge) in #5331, backport #5311).
* **Qdrant TLS metrics**: metrics of TLS-enabled instances are scraped over HTTPS and verified against the issued CA ([**@yankawai**](https://github.com/yankawai) in #5340, backport #5311).
* **Explicit `tenantresource: "false"` is kept**: a Secret created with `internal.cozystack.io/tenantresource: "false"` keeps the label even where its ApplicationDefinition selects the name, so a chart can keep a Secret out of the tenantsecrets projection; a rendered `"true"` is still overwritten by the definition ([**@lllamnyp**](https://github.com/lllamnyp) in #4920, backport #5311).
* **Kubelet config of older tenant Kubernetes versions**: Kamaji stops writing kubelet config fields that older tenant versions do not know, such as `memoryReservationPolicy` before v1.36, so strict decoders of the kubelet-config ConfigMap no longer fail ([**@lexfrei**](https://github.com/lexfrei) in #4896, backport #5311).
* **Tenant hugepages quota**: a quota with `hugepages-2Mi` or `hugepages-1Gi` renders only `requests.hugepages-<size>`, so the tenant installs and its huge pages are bounded ([**@yankawai**](https://github.com/yankawai) in #5189, backport #5311).
* **Tenant etcd alerts and defrag**: tenant etcd alerts are scoped to their release and no longer duplicate the global peer RTT alerts (#5183), and the defrag job requests 10m and 32Mi instead of 200m and 256Mi so it runs in tenants whose quota is almost used up ([**@yankawai**](https://github.com/yankawai) in #5183 and #5100, backport #5311).
* **Tenant namespaces cannot be deleted directly**: a direct DELETE of a tenant namespace is refused unless it comes from helm-controller or the garbage collector, with a pointer to deleting the Tenant, so a namespace deleted by hand no longer sticks in Terminating on Kamaji finalizers ([**@yankawai**](https://github.com/yankawai) in #5011, backport #5311).
* **tcp-balancer Service ports**: the Service publishes ports 6443 and 50000 only when `kubernetesAndTalos` is set, like the Deployment and the HAProxy config; before, every Service carried both ports with nothing behind them ([**@yankawai**](https://github.com/yankawai) in #4965, backport #5311).
* **Operator CRDs on upgrade**: `keycloak-operator` and `foundationdb-operator` replace their CRDs on upgrade. Clusters upgraded from before v1.2.0 kept the v1.25.0 keycloak-operator CRDs, which dropped Keycloak realm session settings, and clusters upgraded from before v1.6.0 kept the v2.13.0 foundationdb-operator CRDs ([**@yankawai**](https://github.com/yankawai) in #4946, backport #5311).
* **LINSTOR error-report alerts**: the alerts no longer fire on old reports when the controller pod moves, a scrape's external label changes or a satellite reconnects within an hour; they count reports per node and carry the node's hostname ([**@yankawai**](https://github.com/yankawai) in #4963, backport #5311).
* **Job and CronJob name limits**: names fit the Kubernetes limits for the longest application names, so a Kafka with a 42 to 44 character name installs, long VMDisk and VMInstance names no longer fail a resize or instance type change, long Bucket and Qdrant names and nested tenant namespaces no longer fail deletion, and long MariaDB and ClickHouse names no longer fail the release with the backup CronJob enabled ([**@yankawai**](https://github.com/yankawai) in #4945, backport #5311).
* **InfoInhibitor no longer pages in Alerta**: it carries severity `none` again, which the platform Alertmanager routes to the blackhole; before, any active `info` alert raised a major InfoInhibitor in Alerta, Telegram and Slack ([**@yankawai**](https://github.com/yankawai) in #4948, backport #5311).
* **VMDisk smaller than its golden image**: a new disk from a golden image is refused at render time with a message naming both sizes, instead of staying pending forever on `CloneValidationFailed`. The default images are 20Gi and the default storage is 5Gi, so such a disk needs `storage` of 20Gi or more ([**@yankawai**](https://github.com/yankawai) in #4960, backport #5311).
* **Hotplug volumes with a missing infra PVC**: stale hotplug volumes are removed when the infra PVC is missing, so deleted volumes no longer block later attachments ([**@yankawai**](https://github.com/yankawai) in #5249, backport #5311).
* **kubevirt-csi RBAC is per cluster**: the kubevirt-csi ClusterRole and ClusterRoleBinding are named after the tenant namespace and the cluster, so deleting a cluster no longer removes PersistentVolume access, and with it volume expansion, from a same-named cluster in another tenant ([**@yankawai**](https://github.com/yankawai) in #5236, backport #5462).
* **ingress-nginx client keepalive**: `keepalive_time` is 12h instead of the nginx default of 1h, so long-lived HTTP/2 connections, such as kopia maintenance against S3, are no longer cut by a GOAWAY after an hour ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5250, backport #5311).
* **vmalert metrics**: the vmalert VMServiceScrape selects the Service the operator creates, so vmalert metrics are collected again ([**@yankawai**](https://github.com/yankawai) in #5094, backport #5311).
* **PostgreSQL backup sidecar CPU**: the barman-cloud sidecar has an explicit one-core CPU limit instead of the tenant LimitRange's 250m default, which made full backups and WAL archiving several times slower. Each instance pod of a tenant with a CPU quota counts 750m more against `limits.cpu` ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5280, backport #5311).
* **External PortList VM without ports**: a VM with an external PortList and an empty list deploys, keeps its external IP and blocks all inbound TCP and UDP ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5270, backport #5311).
* **Monitoring Agents uninstall**: disabling the Monitoring Agents addon of a tenant cluster no longer leaves the release in `UninstallFailed` when the VictoriaMetrics operator is removed first; a pre-delete hook releases the VictoriaMetrics objects' finalizers, and the VPA is rendered only when its CRD is served ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5152, backport #5311).

## Security

* **Talos v1.14.4 (CVE-2026-99999)**: Talos moves from v1.14.2 to v1.14.4 (Linux 6.18.57) to fix a guest-to-host escape through `virtio_net_hdr` checksum offload that any KubeVirt VM can reach on its host node. The fix applies only to the kernel that is running, so upgrade and reboot host nodes ([**@mattia-eleuteri**](https://github.com/mattia-eleuteri) in #5045, backport #5311).
* **System PostgreSQL 17.12 (CVE-2026-116331)**: the system databases of Keycloak, Harbor, Grafana, Alerta and SeaweedFS move from 17.7 to `17.12-standard-trixie` ([**@androndo**](https://github.com/androndo) in #5403, backport #5311).
* **ingress-nginx CVE fixes**: the controller's nginx 1.25.5 is rebuilt with the HTTP/2 fixes for CVE-2026-123633 and CVE-2026-123007 (#5377), and again with the fixes for CVE-2025-23419, CVE-2026-1642, CVE-2026-9256, CVE-2026-42055, CVE-2026-42945, CVE-2026-97629, CVE-2026-118899, CVE-2026-121810, CVE-2026-123634, CVE-2026-125283 and CVE-2026-132779 (#5436); nginx still reports 1.25.5. TLS session tickets are turned off for CVE-2026-97629 while resumption keeps working through the shared session cache (#5407) ([**@kvaps**](https://github.com/kvaps) in #5377, #5436 and #5407, backport #5311).
* **OpenSearch CVE-2026-114938**: nodes start with `-XX:-UseBASE64Intrinsics`, which disables the vulnerable OpenJDK Base64 decoder. Every OpenSearch cluster restarts once on upgrade ([**@androndo**](https://github.com/androndo) in #5373, backport #5311).

## Migration and Upgrades

Platform migrations do not change in this release: `migrations.targetVersion` stays at 61. No release of talm, boot-to-talos, cozyhr, cozy-proxy or external-apps-example fell in this period.

* **Talos host nodes need a reboot (#5045).** Upgrade Talos on the host nodes and reboot them; the kernel fix applies only once the new kernel runs.
* **Pods roll on upgrade.** System PostgreSQL databases of Keycloak, Harbor, Grafana, Alerta and SeaweedFS are rolled, replicas first and then the primary restarted in place, with an interruption of a few minutes per database (#5403). Every OpenSearch cluster restarts once (#5373), ClickHouse pods with backups enabled restart once (#5229), and SeaweedFS s3 pods restart once for the gRPC mTLS change (#5228). ingress-nginx controllers roll for the rebuilt image and configuration (#5377, #5436, #5407).
* **Worker pool rollouts need room for one extra VM (#5153, #5399).** A pool short of quota or capacity stalls with the new Machine Pending until room is made or `maxUnavailable` is set to 1. Set it to 1 on a Proxmox pool whose template passes a GPU through, because the chart cannot see that GPU.
* **Existing etcd members stay put; stranded members need care (#4986).** Only members created after the upgrade get the new spread. An etcd created while the cluster had fewer nodes than members can leave a recreated member Pending after nodes are added, and the node-local volume rules out the other nodes; replace a stranded member by deleting its `EtcdMember` while the others keep quorum, one at a time. To keep the old behaviour, set `scheduling.globalAppTopologySpreadConstraints` in `spec.components.platform.values` of the `cozystack.cozystack-platform` Package to an entry with `maxSkew: 1`, `topologyKey: kubernetes.io/hostname` and `whenUnsatisfiable: ScheduleAnyway` before upgrading.
* **PostgreSQL five-field schedules change meaning (#5119).** A release that already sets five fields gets the standard cron meaning: `0 2 * * *` moves from hourly to daily. Review `backup.schedule` before upgrading.
* **PostgreSQL backup CPU headroom (#5280).** Each instance pod of a tenant with a CPU quota counts 750m more against `limits.cpu`; check the headroom before pods are recreated. Existing ObjectStores pick up the limit at their next backup or HelmRelease upgrade, and running pods at their next restart.
* **Velero backups of already failed BackupJobs are deleted (#5364).** To keep one for a manual `velero restore`, copy it before the upgrade. The `backupstrategy-controller` ClusterRole gains `delete` on `deletebackuprequests`.
* **Lifecycle enforcement and orphan cleanup in SeaweedFS (#5228, #4915).** Enabling `lifecycle.enabled` makes stored rules apply within minutes and deletes objects they already expired on the first pass, so review existing rules first; each enabled instance gains two small pods and a 1Gi volume on `lifecycle.storageClass` or the cluster default. With `cosi.orphanIdentities` at `auto`, orphaned S3 identities are removed on upgrade unless `filer.grpcHost` is set; set `report` if the filer is reachable from other clusters some other way.
* **Tenant super-admins lose direct VirtualMachine writes (#4797).** Automation that creates or edits `kubevirt.io` VirtualMachines as a tenant super-admin must use VMInstance and VMDisk applications instead.
* **Direct deletes of tenant namespaces are refused (#5011).** Delete the Tenant instead.
* **tcp-balancer Services lose unused ports (#4965).** Services without `kubernetesAndTalos` no longer publish 6443 and 50000.
* **kubevirt-csi RBAC objects are renamed (#5236).** The ClusterRole and ClusterRoleBinding of tenant Kubernetes clusters get namespace- and cluster-specific names.
* **Tenant PostgreSQL stays on the v1.7.1 images (#5405 was reverted in #5461).** v1.7.2-rc.1 carried a move of tenant PostgreSQL to patched `standard-trixie` images, taken out again after an upgrade test from v1.7.1 found blockers. Upgrading from v1.7.1 changes no tenant PostgreSQL image, so CVE-2026-116331 remains open for tenant PostgreSQL on v1.7 until the move returns in a later patch. A cluster that ran v1.7.2-rc.1 goes back to the bullseye images on this release without a collation rebuild, so indexes on non-C collations need a `REINDEX`, and a PostGIS extension already updated to 3.7.0 does not load with the 3.6.1 image.
